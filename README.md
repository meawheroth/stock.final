
# ระบบคลังวัสดุและอุปกรณ์

เว็บแอปสำหรับจัดการครุภัณฑ์และวัสดุสิ้นเปลือง พร้อมส่งคำขอยืม อนุมัติ เบิกจ่าย และบันทึกการรับคืน

## ความสามารถหลัก

- แสดงจำนวนคงเหลือ แยกตามหมวดและสถานะของอุปกรณ์
- ค้นหาและกรองรายการในคลัง
- ส่งคำขอยืมพร้อมระบุโปรเจกต์ วัตถุประสงค์ และวันกำหนดคืน
- อนุมัติหรือปฏิเสธคำขอโดยผู้ดูแลระบบ
- บันทึกคืนครุภัณฑ์ได้เป็นจำนวนและสภาพ เช่น พร้อมใช้ ชำรุด เสีย หรือสูญหาย
- แสดงประวัติคำขอ สถานะเกินกำหนด และสรุปการใช้งาน
- จัดการบัญชีนักศึกษาและอาจารย์ รวมถึงอาจารย์ที่ดูแลนักศึกษา

## บทบาทผู้ใช้

- **นักศึกษา**: ดูคลัง ส่งคำขอยืม และติดตามสถานะคำขอของตนเอง
- **อาจารย์**: ดูคำขอและข้อมูลของนักศึกษาที่ตนเองดูแล
- **Admin**: จัดการคลัง อนุมัติคำขอ รับคืนครุภัณฑ์ และสร้างบัญชีผู้ใช้

## เทคโนโลยี

- Node.js และ Express
- MongoDB และ Mongoose
- หน้าเว็บ HTML, CSS และ JavaScript แบบ static ใน `public/`

## สิ่งที่ต้องมี

- Node.js 18 ขึ้นไป
- MongoDB ที่รองรับ transaction เช่น MongoDB Atlas หรือ MongoDB replica set

ระบบใช้ transaction ตอนอนุมัติคำขอและบันทึกคืน เพื่อให้การเปลี่ยนยอดคลังกับประวัติคำขอสำเร็จหรือยกเลิกพร้อมกัน MongoDB standalone ไม่รองรับการทำงานส่วนนี้

## ติดตั้งและเริ่มระบบในเครื่อง

1. ดาวน์โหลดหรือ clone repository
2. ติดตั้ง dependencies:

   ```sh
   npm ci
   ```

3. คัดลอก `.env.example` เป็น `.env` แล้วใส่ค่าจริง
4. เริ่มระบบ:

   ```sh
   npm start
   ```

5. เปิด `http://localhost:3000`

ระหว่างพัฒนาใช้คำสั่ง `npm run dev` เพื่อเริ่ม Node.js watch mode

## Environment variables

| ชื่อตัวแปร | จำเป็น | รายละเอียด |
|---|---|---|
| `MONGODB_URI` | ใช่ | Connection string ของ MongoDB |
| `JWT_SECRET` หรือ `TOKEN_SECRET` | ใช่ | Secret สำหรับลงลายเซ็น token ควรเป็นค่าสุ่มที่คาดเดายาก |
| `ADMIN_EMAIL` | ไม่บังคับ | อีเมลสำหรับสร้างบัญชี Admin เริ่มต้น |
| `ADMIN_PASSWORD` | ไม่บังคับ | รหัสผ่าน Admin เริ่มต้น ใช้คู่กับ `ADMIN_EMAIL` |
| `PORT` | ไม่ | พอร์ตเว็บเซิร์ฟเวอร์ ค่าเริ่มต้น 3000; Render กำหนดให้อัตโนมัติ |

ถ้ากำหนด `ADMIN_EMAIL` และ `ADMIN_PASSWORD` ระบบจะสร้างบัญชี Admin เมื่อยังไม่มีบัญชีอีเมลนั้น หากอีเมลมีบัญชีที่ไม่ใช่ Admin อยู่แล้ว ระบบจะหยุดเริ่มต้นเพื่อป้องกันการให้สิทธิ์ผิดบัญชี

ห้าม commit ไฟล์ `.env` หรือส่ง secret ขึ้น GitHub ให้ใช้ Environment settings ของบริการที่ deploy แทน

## Deploy บน Render

1. สร้าง **Web Service** จาก repository นี้
2. ตั้ง **Build Command** เป็น `npm ci`
3. ตั้ง **Start Command** เป็น `npm start`
4. เพิ่ม Environment Variables ตามตารางด้านบนในหน้า Render
5. ตั้ง Health Check Path เป็น `/api/health`
6. Deploy แล้วตรวจหน้า Logs ว่าเชื่อมต่อ MongoDB สำเร็จและเว็บเริ่มทำงาน

ไม่ต้องกำหนด `PORT` เองบน Render เว้นแต่มีเหตุผลเฉพาะ เพราะ Render ส่งค่านี้ให้ service โดยอัตโนมัติ

## กฎสถานะและจำนวนสต็อก

- สถานะ `pending`: รอ Admin ตรวจสอบ
- สถานะ `approved`: กำลังยืมครุภัณฑ์ รอรับคืน
- สถานะ `returned`: รับคืนครุภัณฑ์ครบแล้ว
- สถานะ `dispensed`: อนุมัติและเบิกจ่ายวัสดุสิ้นเปลืองแล้ว วัสดุถือว่าใช้ไป
- สถานะ `rejected`: Admin ไม่อนุมัติคำขอ
- จำนวนที่ถูกยืมเปลี่ยนผ่านขั้นตอนอนุมัติและรับคืน ไม่ควรแก้โดยตรงจากหน้าปรับสต็อก

## API ที่ใช้ตรวจสอบ

- `GET /api/health` — ตรวจสถานะเว็บและ MongoDB; ตอบ HTTP 503 เมื่อฐานข้อมูลไม่พร้อม
- `/api/auth` — สมัคร เข้าสู่ระบบ และจัดการบัญชีผู้ใช้ตามสิทธิ์
- `/api/items` — ดูและจัดการรายการคลังตามสิทธิ์
- `/api/loans` — ส่งคำขอ อนุมัติ บันทึกคืน และดูสรุปคำขอ

## แก้ปัญหาเบื้องต้น

- **ระบบหยุดพร้อมข้อความ Missing required environment variables**: ตรวจ `MONGODB_URI` และ `JWT_SECRET` หรือ `TOKEN_SECRET`
- **เชื่อมต่อ MongoDB ไม่ได้**: ตรวจ connection string, รหัสผ่าน, network access list และสิทธิ์ของ database user
- **transaction ไม่รองรับ**: ใช้ MongoDB Atlas หรือ replica set แทน standalone MongoDB
- **เริ่มระบบไม่ได้เพราะ `ADMIN_EMAIL` มีบัญชีอยู่แล้ว**: ตรวจ role ของบัญชีนั้น หรือกำหนดอีเมล Admin เริ่มต้นที่ถูกต้อง
- **หน้าเว็บแสดงข้อมูลผิดหลัง deploy**: ตรวจว่า Render deploy commit ล่าสุดจาก branch ที่ต้องการ และ reload หน้าเว็บ
